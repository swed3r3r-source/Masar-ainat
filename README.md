# مسار عينات

منصة لتخطيط وتشغيل ومراقبة نقل العينات الطبية بين المنشآت الصحية والمختبرات.
التخطيط بمحرّك تحسين رياضي (PDPTW متعدد المراكز)، والتنفيذ عبر تطبيق سائق،
والصلاحيات مطبَّقة في الخادم **وفي قاعدة البيانات** معًا.

> **اقرأ [`STATUS.md`](STATUS.md) قبل أي قرار اعتماد.** فيه ما يعمل فعلًا، وما
> يعمل بالتقدير، وما هو محوّل بلا خدمة — بالأرقام لا بالوصف. أهمّ بندين:
> **OSRM غير متصل حيًّا في هذه النسخة**، و**OR-Tools غير مثبَّتة**.

## ١. المتطلبات

| المكوّن | الحد الأدنى | ملاحظة |
|---|---|---|
| PostgreSQL | **16** | مع `pgcrypto` و`btree_gist` |
| Python | **3.11** | |
| المعالج | ٤ أنوية | التخطيط متوازٍ — كل نواة إضافية تقصّر زمن الخطة |
| الذاكرة | ٨ ج.ب | |
| القرص | ١٠٠ ج.ب + مساحة النسخ | جدول مواقع السائقين مقسَّم وينمو بسرعة |

حزم Python المطلوبة قليلة عمدًا: عميل PostgreSQL مكتوب داخل المشروع
(`packages/pgwire`)، فلا حاجة إلى `psycopg` ولا إلى أي امتداد يحتاج ترجمة.

## ٢. التشغيل من الصفر — ست خطوات

```bash
# ١) الاعتماديات
#    على خادم متصل بـPyPI ولّد القفل أولًا ثم ثبّت به (الطريق المعتمد):
#        ./scripts/lock_dependencies.sh
#        pip install --require-hashes -r requirements.lock
#    وإلا (تطوير محلي فقط):
python3 -m pip install -r requirements.txt

# ٢) الإعداد — انسخ القالب وولّد الأسرار
cp .env.example .env.dev
$EDITOR .env.dev
#   MASAR_DB_PASSWORD, MASAR_DB_MIGRATE_PASSWORD → openssl rand -base64 24
#   MASAR_JWT_SECRET                             → openssl rand -base64 48
#   MASAR_ENCRYPTION_KEYS  → dev1:$(python3 -c \
#       "import base64,os;print(base64.b64encode(os.urandom(32)).decode())")

set -a; . ./.env.dev; set +a

# ٣) قاعدة البيانات — عنقود محلي معزول على المنفذ 55432
./scripts/pg.sh init

# ٤) الترحيلات
PYTHONPATH=packages python3 -m masar_db.migrate up

# ٥) بيانات تجربة موسومة (اختياري لكنه يجعل الواجهة قابلة للاستكشاف فورًا)
PYTHONPATH=packages python3 scripts/seed.py
#   يطبع كلمة مرور عشوائية للحسابات التجريبية — مرة واحدة، ولا تُحفظ في ملف

# ٦) الخادم
./scripts/serve.sh start
```

ثم افتح:

| الواجهة | العنوان | لمن |
|---|---|---|
| المكتب | `http://127.0.0.1:8080` | المدير · التخطيط المركزي · مشرف المركز · برج التحكم · المدقق |
| تطبيق السائق | `http://127.0.0.1:8080/driver` | السائق (مصمَّم للجوال) |
| الجهة الطالبة | `http://127.0.0.1:8080/request` | المنشآت الخارجية — طلب فوري |

**للفتح من الجوال على الشبكة نفسها:** بدّل `--host 127.0.0.1` إلى
`--host 0.0.0.0` في `scripts/serve.sh`. لا تفعل ذلك على شبكة عامة — إعداد
التطوير بلا TLS.

## ٣. التحقق من أن كل شيء يعمل

```bash
./scripts/run_tests.sh
```

يعيد بناء القاعدة، ويزرع بيانات موسومة، ويشغّل الخادم، ثم ينفّذ الحزمة كاملة
ويطبع **مصفوفة تغطية** لكل سيناريو من السيناريوهات الإلزامية الستة والأربعين:
أي سيناريو غُطّي، بأي اختبار، وبأي نتيجة. سيناريو بلا اختبار يظهر «غير مُغطى»
صراحةً — لا يمر بصمت. أي اختبار لا ينجح يُذكر **بالاسم والسبب**.

النتيجة المتوقعة على نسخة سليمة:

```
الاختبارات : 181 · ناجحة 181 · فاشلة 0 · متخطّاة 0
السيناريوهات: 46 · مثبتة 46 · فاشلة 0 · غير منفَّذة 0 · غير مُغطاة 0
```

تشغيلات جزئية:

```bash
PYTHONPATH=packages python3 tests/run_tests.py --unit        # بلا قاعدة ولا خادم
PYTHONPATH=packages python3 tests/run_tests.py --security    # الفحوص الهجومية
PYTHONPATH=packages python3 scripts/osrm_adapter_check.py    # محوّل الطرق (خادم وهمي)
PYTHONPATH=packages python3 scripts/preflight.py             # جاهزية الإقلاع
PYTHONPATH=packages python3 scripts/ui_roles_check.py "$(cat accounts.json)"  # واجهات كل الأدوار
```

**اختبار المتصفح الحقيقي** (يتطلب `playwright` و`python3 -m playwright install chromium`):

```bash
PYTHONPATH=packages python3 scripts/browser_walkthrough.py "$(cat accounts.json)"
```
ينفّذ الدورة العشرينية كاملة — من رفع الجدول إلى ظهور العملية في سجل التدقيق —
بالنقر والكتابة في متصفح فعلي، ويلتقط صورة لكل خطوة في `var/shots/`.

## ٤. خريطة المستودع

```
packages/
  masar_core/   القواعد الحاكمة: الإعداد، الصلاحيات، آلات الحالة، التشفير، الأمان
  masar_db/     التعامل مع القاعدة + الترحيلات (مصدر الحقيقة للمخطط)
  masar_opt/    محرّك التحسين: النموذج، التقييم، الحل الاستدلالي، الحل المضبوط، مزوّدو الطرق
  masar_api/    طبقة HTTP والخدمات التطبيقية
  pgwire/       عميل PostgreSQL (بروتوكول wire ٣ + SCRAM-SHA-256) مكتوب داخل المشروع
web/            الواجهات الثلاث — بلا إطار عمل ولا خطوة بناء
tests/          ٥ وحدات + مصفوفة تغطية السيناريوهات الإلزامية
scripts/        التشغيل والزرع والنسخ والفحوص وأدوات التحقق
deploy/         systemd · nginx · قالب الإنتاج · حزمة OSRM · حزمة staging بـDocker
db/schema.sql   لقطة مخطط مرجعية (بنية فقط) — الترحيلات هي المرجع
docs/           ١٢ وثيقة: المتطلبات، المعمارية، البيانات، الحالات، API، الأمان، النشر
```

## ٥. المبادئ التي بُني عليها

هذه ليست شعارات — كل بند منها **مُختبَر** في الحزمة:

- **الصلاحيات في الخادم وفي القاعدة.** إخفاء الأزرار ليس أمانًا. ٧٤ سياسة أمن
  صفوف تُطبَّق حتى لو تسرّب اتصال مباشر بقاعدة البيانات.
- **لا بيانات وهمية تُعرض كحقيقية.** كل تكامل غائب يُعلن غيابه: الحساسات
  `NO_SENSOR`، والإشعارات `NO_PROVIDER`، وأزمنة الطرق «تقديرية» بوسم ظاهر.
- **كل خطة تمر بفحص رياضي وتشغيلي** قبل قبولها، وكل تحذير مرتبط برحلة أو شحنة
  وسبب مصنَّف وإجراء مقترح.
- **لا نسبة تحسين بلا خطة أساس معلنة.** الشاشة تقول ذلك صراحةً عند غيابها.
- **السائق لا يُدخل الحرارة يدويًا.** لا يوجد مسار API يسمح بذلك لدور السائق.
- **سجل التدقيق غير قابل للتعديل** — `REVOKE UPDATE, DELETE` على مستوى القاعدة.
- **لا حذف نهائي للبيانات التشغيلية** بلا صلاحية خاصة.
- **بيانات الاختبار موسومة** `is_test_data`، ومحفّز في القاعدة يرفض دخولها
  بيئة الإنتاج.
- **لا كلمات مرور ولا مفاتيح في المستودع.** الزرع يولّد كلمة مرور ويطبعها مرة
  واحدة؛ ولا قيمة افتراضية في الكود.

## ٥أ. البيئة التجريبية (staging) بأمر واحد

حزمة كاملة بـDocker: التطبيق · PostgreSQL 16 · OSRM ذاتي الاستضافة ·
nginx بـHTTPS. فحص صحي لكل خدمة، وvolumes دائمة، وشبكة داخلية **لا تكشف
قاعدة البيانات ولا OSRM ولا المنفذ 8080** — الوصول عبر HTTPS فقط.

```bash
./scripts/staging-up.sh      # التشغيل (يولّد الأسرار والحسابات عند التشغيل)
./scripts/staging-test.sh    # التحقق: عزل الشبكة · HTTPS · التشفير · الطرق
```

الدليل الكامل لغير التقني: [`deploy/staging/README.md`](deploy/staging/README.md).

## ٦. النشر إلى الإنتاج

الدليل الكامل في [`docs/11-deployment-runbook.md`](docs/11-deployment-runbook.md) —
المتطلبات، الأدوار، الترحيلات، أرشفة WAL، وحدات systemd، nginx، المراقبة،
والاستعادة من كارثة.

بوابة الإقلاع:

```bash
PYTHONPATH=packages python3 scripts/preflight.py
```

يفشل بقائمة موانع محددة عند أي إعداد ناقص أو ضعيف، وهو نفسه `ExecStartPre` في
وحدة systemd — فالخدمة لن تبدأ بإعداد يرفضه. من موانعه في الإنتاج: سر JWT ضعيف،
تشفير تخزين غير مفعّل، ترحيلات معلّقة، سياسات RLS ناقصة، بيانات اختبار في قاعدة
الإنتاج، ومزوّد طرق تقديري أو خريطة لا تطابق المرجع.

**لتفعيل مزوّد طرق حقيقي:** `./deploy/osrm/activate.sh` — ست بوابات كل واحدة
توقف الباقي عند فشلها. التفاصيل في [`deploy/osrm/README.md`](deploy/osrm/README.md).
