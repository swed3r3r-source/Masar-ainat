## ملخص تنفيذي

| البند | الحالة |
|---|---|
| السيناريوهات الإلزامية (§30) | **٤٦/٤٦ مثبتة** · ٠ فاشلة · ٠ غير مُغطاة |
| الاختبارات الآلية | **١٦٠** · ناجحة ١٥٩ · فاشلة ٠ · متخطّاة ١ |
| الدورة الكاملة عبر HTTP | ✅ نجحت كل الفحوص |
| اختبار المتصفح (٥ واجهات × ٣ مقاسات) | ✅ نجحت كل فحوص الواجهة |
| النسخ الاحتياطي + أرشفة WAL | ✅ متحقَّق منهما آليًا |
| التشفير عند التخزين | ✅ مفعّل ومختبَر (AES-256-GCM) |
| التخطيط المتوازي | ✅ ×1.93 على نواتين · نتيجة مطابقة للتتابعي |
| **الجاهزية للتشغيل الحقيقي** | **مشروطة** — انظر §٧ |

النظام يُنجز الدورة التي عرّفها الطلب: من رفع الجدول إلى تسليم العينات
وتوثيق التنفيذ والتقارير. ما يتبقى **ليس شيفرة**: ثلاثة تكاملات خارجية
تحتاج خدمات وأجهزة، وقرارات استضافة وامتثال، ومراجعة أمنية مستقلة.

## ١. البنية والحجم

| المكوّن | التقنية | الحجم |
|---|---|---|
| قاعدة البيانات | PostgreSQL 16 · ٨ ملفات ترحيل | ٥٠ جدولًا · ٧٤ سياسة RLS · ٦٤ محفّزًا |
| الخادم | Python 3.11 + ASGI/Starlette + uvicorn | ٩٣ مسار API · ٥٦ صلاحية |
| محرك التحسين | مبني من الصفر (Regret-k + ALNS) · متوازٍ بالعمليات | ~٢٬٢٠٠ سطر |
| الواجهة | JavaScript خالص (ES modules) · RTL · PWA | ~٦٬٠٠٠ سطر |
| الاختبارات | `unittest` + Playwright | ١٦٠ اختبارًا |

### قيد بيئي حاسم

**مستودعات الحزم (PyPI و npm) محجوبة في بيئة التطوير هذه (HTTP 403).** لذلك
كُتب من الصفر: عميل PostgreSQL (`pgwire`)، ومحرك التحسين، وعارض الخريطة.
كلها خلف نقاط استبدال موثّقة (`masar_db/driver.py`، `masar_opt/backends.py`).

**استثناء مهم:** مكتبة `cryptography` **متوفرة** في هذه البيئة، فالتشفير عند
التخزين يعمل بـ AES-256-GCM من مكتبة مُراجَعة — لا بتنفيذ يدوي. التنفيذ
المحلي لـ ChaCha20-Poly1305 موجود كمسار احتياطي فقط، ومُثبَت بمتجهات
RFC 8439 الرسمية في الاختبارات.

## ٣. الأخطاء التي اكتُشفت وأُصلحت

### في مرحلة بناء حزمة §30

| # | الخطأ | الأثر لولا الاكتشاف |
|---|---|---|
| ١ | `IndexError` في تقدير السائقين — قائمة مركبات مصفّاة بأرقام أصلية | انهيار شاشة التقدير في كل مركز متعدد السائقين |
| ٢ | **مقدم الطلب لا يرى طلباته** — ربط داخلي بجدول خارج نطاقه يُسقط صفوفه بصمت | ميزة معطّلة، واختفاء بلا رسالة خطأ |
| ٣ | `AlertType.DELIVERY_LATE` معرَّف ولا يُرفع أبدًا | تأخر التسليم لا يُنبَّه عليه إلا بعد فوات SLA |
| ٤ | إعادة مزامنة حدث استثناء تُنشئ سجلًا ثانيًا | تضخّم السجلات بعد كل انقطاع شبكة |
| ٥ | تجاوز منتصف الليل في مولّد الجدول | جدول اختبار كامل خارج أوقات العمل |
| ٦ | البناء `O(S²·V·L²)`: ٨٠ شحنة في ٣١٦ ثانية | ادّعاء «نطاق وطني» غير قابل للتحقق |
| ٧ | ١٢ إعدادًا بلا وصف عربي | شاشة إعدادات بمفاتيح غير مفهومة |

### في مرحلة استكمال الجاهزية

| # | الخطأ | الأثر لولا الاكتشاف |
|---|---|---|
| ٨ | **كشف إعادة استخدام رمز التحديث كان مستحيلًا** — التدوير يستبدل التجزئة في مكانها فلا يبقى للرمز القديم أثر، وفرع الكشف غير قابل للوصول | رمز تحديث مسروق يمنح المهاجم جلسة حية بينما يفشل المستخدم الشرعي بصمت ويعيد الدخول — والمهاجم يبقى داخلًا |
| ٩ | **إبطال الجلسات كان يُلغى بالتراجع** — التحديث يجري داخل معاملة ثم يُرفع الاستثناء فيها فتتراجع كتابته | حتى بعد إصلاح ٨، الإبطال بلا أثر فعلي |
| ١٠ | **طلب فوري يُدرج في رحلة جارية يشلّها** — الشحنة تبقى `PUBLISHED` ولا يوجد انتقال منها إلى `ARRIVED_PICKUP`، ولأن ترتيب المحطات مُلزم فإنها **تحجب كل ما بعدها** | كل رحلة يُدرج فيها طلب فوري بعد بدء السائق تصبح غير قابلة للإكمال |
| ١١ | **الطلب الفوري بلا وقت تسليم مخطط** — الإدراج لا يعيد حساب الجدول الزمني | لا تنبيه تأخر للطلبات الفورية، وغيابها عن مقارنة الخطة بالتنفيذ |
| ١٢ | **معرّف غير صالح ⇒ خطأ خادم ٥٠٠** | تصنيف خاطئ يخفي خطأ المستخدم ويشوّش مراقبة الأعطال الحقيقية |
| ١٣ | **فحص الإنتاج لا يرفض مفتاح JWT التطويري** | نشر إنتاج بمفتاح معروف ⇒ أي شخص يصنع رمز مدير نظام |
| ١٤ | **إعادة تشغيل المحرك على يوم مسودة تفشل** — `PLANNED ← UNPLANNABLE` غير مسموح، وتفريغ سبب التعذر قبل تغيير الحالة يخرق قيدًا | إعادة التخطيط تُسقط التشغيل كله |
| ١٥ | الخادم يعلن مكدّسه وإصداره في الترويسات | يختصر على المهاجم خطوة الاستطلاع |

**الأخطاء ٨ و٩ و١٠ و١٢ و١٣ خطيرة**، وثلاثة منها أمنية. كلها كُشفت بحزم
الاختبار لا بالمراجعة البصرية.

## ٤. الأداء المقيس

### المحرك (مركز واحد، مهلة ١٥ ثانية)

| الشحنات | زمن الحل | الرحلات | المخطط |
|---|---|---|---|
| ٤٠ | ~١٥ ث | ٦ | ٤٠/٤٠ |
| ٨٠ | ~١٧ ث | ١٠ | ٨٠/٨٠ |
| ٣٠٠ | ~٢٧ ث | ٣٠ | ٣٠٠/٣٠٠ |

### التوازي (٤٨٠ شحنة، ٤ مراكز × يومين = ٨ مسائل)

```
متتابع : 46.7 ث
متوازٍ : 24.2 ث على عمليتين  →  ×1.93
تطابق النتيجة بين الوضعين: ✅ نعم
```

التسريع شبه خطي لأن المسائل **مستقلة رياضيًا**: لا قيد يربط رحلة في مركز
برحلة في مركز آخر. على عتاد إنتاجي بـ ١٦ نواة يُتوقع تسريع مقارب — **لكنه
غير مقيس**، فالبيئة الحالية بنواتين.

### الاستعادة

`backup.sh measure` على حجم البيانات الحالي (١٧ م.ب): نسخ < ١ ث، استعادة ١ ث.
**الرقم يتناسب مع الحجم — أعد القياس على حجم الإنتاج قبل ادّعاء تحقيق RTO.**

## ٥. التكاملات: حقيقي مقابل محاكاة

| التكامل | الحالة | ماذا يُعرض للمستخدم | ما ينقص للتفعيل |
|---|---|---|---|
| **قاعدة البيانات** | ✅ حقيقي | — | — |
| **التشفير عند التخزين** | ✅ حقيقي (AES-256-GCM) | حالة التشفير في `/api/storage/status` | إدارة المفاتيح عبر خزنة بدل البيئة |
| **أرشفة WAL** | ✅ تعمل | — | نقل الأرشيف إلى تخزين منفصل |
| **مزوّد الطرق** | ⚠️ **تقديري معلن** | `routing_estimated: true` + تحذير HIGH على كل خطة | استضافة OSRM + `MASAR_ROUTING_PROVIDER=osrm` |
| **حساس الحرارة** | ⚠️ **لا مزوّد** | `NO_SENSOR` صراحةً — لا صفر ولا قيمة مُولَّدة | مزوّد حساسات + مفتاح |
| **الإشعارات** | ⚠️ **لا مزوّد** | `NO_PROVIDER` في الصندوق — لا يُوسم «مُرسَل» | SMTP أو مزوّد رسائل |
| **خلفية OR-Tools** | ⚠️ غير مثبّتة | `DependencyUnavailable` برسالة تشرح التفعيل | `pip install ortools` |
| **تخزين S3** | ⚠️ غير منفَّذ | يعمل بالتخزين المحلي | `boto3` + تنفيذ الجسم |
| **الهوية المؤسسية (SSO)** | ❌ غير منفَّذة | مصادقة محلية | تكامل OIDC/SAML |

**لم تُعرض محاكاة على أنها تكامل حقيقي في أي شاشة.**

## ٦. الأخطاء المفتوحة والقيود المعروفة

**لا يوجد خطأ مفتوح معروف يُفشل اختبارًا.** القيود:

1. **التوازي مقيس على نواتين فقط** — هذا ما توفّره البيئة. السلوك خطي والنتيجة
   مطابقة، لكن القياس على ١٦ نواة لم يجرِ.
2. **جودة الحل مقابل السرعة.** ترشيح مواضع الإدراج قد يفوّت موضعًا أرخص. لا
   يمكنه قبول رحلة غير شرعية، لكن الفارق عن الأمثل غير مقيس لأحجام كبيرة.
3. **لا اختبار حِمل متزامن على API** — اختبار الضغط على المحرك لا على الخادم.
4. **`pgwire` مكتوب من الصفر** — مختبَر عبر كل مسارات النظام، لكنه ليس بنضج
   `psycopg` (لا `COPY`، ولا SSL مختبَر).
5. **الفحوص الأمنية تقييم ذاتي** — تكشف الواضح ولا تُغني عن اختراق مستقل.
6. **إدارة المفاتيح عبر متغيرات البيئة** — مقبول كحد أدنى، والأصح خزنة أسرار
   مع تدوير مجدول.
7. **أوقات عمل المراكز تُوسَّع في بيئة الاختبار** خارج الدوام، عبر API الإدارة
   نفسه. تغيير إعداد لا تجاوز قيد — والمحرك يبقى يفحص كل رحلة مقابل النافذة
   المُعلنة.

## ٧. ما يتبقى قبل الجاهزية التشغيلية

**كل ما تبقى خارج الشيفرة.** لا يوجد بند واحد ينتظر تطويرًا:

| # | المطلوب | النوع | من يملك القرار |
|---|---|---|---|
| ١ | **استضافة OSRM** أو التعاقد مع مزوّد طرق | تشغيلي · مالي | قرار إداري (§٨-١) |
| ٢ | **خزنة أسرار** لإدارة مفاتيح التشفير بدل متغيرات البيئة | امتثال | البنية التحتية |
| ٣ | **توطين الاستضافة داخل المملكة** وفق إطار الحوسبة السحابية | امتثال | قرار إداري (§٨-٢) |
| ٤ | **اختبار اختراق مستقل** من جهة خارجية | امتثال | تعاقد |
| ٥ | **حساسات حرارة** — بدونها تبقى الرقابة الحرارية `NO_SENSOR` | تشغيلي · مالي | قرار إداري (§٨-٣) |
| ٦ | **مزوّد رسائل/بريد** لتفعيل الإشعارات الخارجية | تشغيلي | قرار إداري |
| ٧ | نقل أرشيف WAL إلى تخزين منفصل عن الخادم | تشغيلي | البنية التحتية |
| ٨ | تركيب OR-Tools ومقارنته بالخلفية الحالية على بيانات حقيقية | جودة الحل | اختياري |
| ٩ | استبدال `pgwire` بـ `psycopg 3` | متانة | اختياري |
| ١٠ | تكامل SSO | تكامل | اختياري |
| ١١ | بيانات إنتاج حقيقية وتدريب المشغّلين | تشغيلي | الجهة المالكة |

**الحد الأدنى للتشغيل الحقيقي: البنود ١–٥.** البنود ٦–١١ تحسينات لا موانع.

## ٨. القرارات التي تنتظر موافقتك

وقفت عندها كما يطلب §3 (قرار مالي أو أمني جوهري):

1. **استضافة مزوّد الطرق.** OSRM ذاتي الاستضافة (تكلفة خادم، بلا رسوم
   استخدام، **البيانات لا تغادر**) مقابل مزوّد تجاري (رسوم مستمرة، وإرسال
   إحداثيات مرافق صحية إلى طرف ثالث — قرار أمني لا تقني).
2. **موقع الاستضافة.** سحابة داخل المملكة مقابل مركز بيانات حكومي.
3. **مزوّد حساسات الحرارة.** يحدد شكل المحوّل ودورية القراءة والتكلفة لكل صندوق.
4. **سياسة الاحتفاظ بالبيانات.** كم تُحفظ إحداثيات السائقين وقراءات الحرارة؟
   (يؤثر على التقسيم والأرشفة وعلى الامتثال معًا.)

## ٩. كيف تشغّل النظام وتتحقق بنفسك

```bash
./scripts/pg.sh start
PYTHONPATH=packages python3 scripts/seed.py --reset
./scripts/serve.sh restart

PYTHONPATH=packages python3 scripts/preflight.py    # فحص جاهزية الإقلاع
./scripts/run_tests.sh                              # ٤٦ سيناريو + مصفوفة التغطية
python3 tests/run_tests.py --security                # الفحوص الأمنية وحدها
./scripts/run_e2e.sh                                 # الدورة الكاملة عبر HTTP
PYTHONPATH=packages python3 scripts/ui_test.py       # المتصفح
./scripts/backup.sh verify                           # النسخ والاستعادة وأرشفة WAL
./scripts/backup.sh measure                          # قياس RTO الفعلي
PYTHONPATH=packages python3 scripts/bench_national.py 60 2   # قياس التوازي
PYTHONPATH=packages python3 scripts/gen_docs.py      # إعادة توليد الوثائق
```

`sup.ryd@` · `sup.arr@` · `tower@` · `auditor@` · `req.phc01@` ·
`drv-ryd-01@` — كلها على النطاق `masar.test`.

النشر في الإنتاج: **`docs/11-deployment-runbook.md`**.
