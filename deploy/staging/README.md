# تشغيل البيئة التجريبية — دليل خطوة بخطوة

> هذا الدليل مكتوب لمن سيُشغّل النظام، لا لمن كتبه. لا يُفترض فيك معرفة سابقة
> بـDocker. اتبع الخطوات بالترتيب، وانسخ الأوامر كما هي.

---

## ما هي «البيئة التجريبية»؟

نسخة كاملة من النظام تعمل على خادم واحد، **ببيانات وهمية**، لتجربة كل شيء قبل
الإنتاج. تشمل خمس خدمات تعمل معًا تلقائيًا:

| الخدمة | دورها |
|---|---|
| **التطبيق** | النظام نفسه: التخطيط والتشغيل والتقارير |
| **قاعدة البيانات** | PostgreSQL 16 — تحفظ كل شيء |
| **خدمة الطرق (OSRM)** | تحسب المسافات والأزمنة على **طرق السعودية الحقيقية** |
| **nginx** | البوابة الوحيدة من الخارج، ويفرض HTTPS |
| **تجهيز الخرائط** | يعمل مرة واحدة فقط لبناء بيانات الطرق |

---

## قبل أن تبدأ — ثلاثة أشياء يجب أن تعرفها

**١. البيانات كلها وهمية، وهذا شرط لا خيار.** كل صف تُنشئه هذه البيئة موسوم
`is_test_data`، وقاعدة البيانات نفسها ترفض هذه الصفوف في الإنتاج. **لا تُدخل
بيانات مرضى حقيقية ولا بيانات تشغيل فعلية هنا إطلاقًا** — البيئة التجريبية
أقل تحصينًا، وشهادتها موقَّعة ذاتيًا، والوصول إليها أوسع.

**٢. محرك التخطيط هو `native_alns`، و OR-Tools غير مثبَّتة.** إن قرأت في مكان
ما أن النظام يستخدم OR-Tools فهذا غير صحيح: الموجود محوّل فقط بلا تنفيذ.
المحرك الفعّال مُختبَر وفجوة أمثليته صفر مقابل حل مضبوط على الأحجام القابلة
للتحقق. راجع `STATUS.md`.

**٣. لا تنسخ كلمات المرور إلى ملف.** السكربت يولّدها عند التشغيل ويعرضها
**مرة واحدة**. إن ضاعت، ولّد مجموعة جديدة بأمر واحد (في آخر هذا الدليل).

## المتطلبات

| | الحد الأدنى |
|---|---|
| نظام التشغيل | Linux (أو macOS مع Docker Desktop) |
| Docker | مثبَّت ويعمل |
| الذاكرة | **٨ ج.ب** (تجهيز الخرائط أثقل خطوة) |
| المساحة الحرة | **٢٥ ج.ب** |
| الوقت | ٢٠–٤٠ دقيقة أول مرة، ودقيقتان بعدها |
| الإنترنت | مطلوب أول مرة لتنزيل الخريطة والصور |

للتأكد أن Docker يعمل:

```bash
docker info
```

إن ظهر خطأ: `sudo systemctl start docker`

## الخطوة ١: التشغيل

من مجلد المشروع، أمر واحد:

```bash
./scripts/staging-up.sh
```

سيمر بثماني خطوات ويطبع تقدّمه. **إن توقّف عند أي خطوة فاقرأ الرسالة** — كل
رسالة توقّف تقول ما الخطأ وما العمل.

| # | الخطوة | ماذا يحدث |
|---|---|---|
| ١ | فحص المتطلبات | يتأكد من Docker والذاكرة والمساحة قبل بدء عمل طويل |
| ٢ | توليد الأسرار | ينشئ كلمات مرور ومفاتيح تشفير عشوائية في ملف محمي |
| ٣ | شهادة HTTPS | يولّد شهادة تجريبية موقَّعة ذاتيًا |
| ٤ | **بيانات الطرق** | ينزّل خريطة السعودية ويجهّزها — **١٠–٢٥ دقيقة** |
| ٥ | تشغيل الخدمات | يبني ويشغّل الخمسة وينتظر جاهزية كل واحدة |
| ٦ | الترحيلات والبيانات | ينشئ الجداول ويزرع بيانات وهمية موسومة |
| ٧ | التحقق من الطرق | يقارن بمسافات سعودية معروفة — يفشل إن كانت الخريطة خاطئة |
| ٨ | الحسابات | ينشئ حسابات التجربة ويطبع كلمات مرورها **مرة واحدة** |

> **الخطوة ٤ تبدو متوقفة وهي تعمل.** تجهيز الخريطة لا يطبع شيئًا لدقائق. لا
> تقاطعها. إن انتهت فجأة بلا رسالة فالسبب غالبًا نفاد الذاكرة — أضف ذاكرة.

### احفظ كلمات المرور الآن

في نهاية التشغيل ستظهر جدولة كهذه:

```
ADMIN                trial.admin@masar.test         <كلمة مرور عشوائية>
CENTRAL_PLANNER      trial.planner@masar.test       <كلمة مرور عشوائية>
HUB_SUPERVISOR       trial.super.ryd@masar.test     <كلمة مرور عشوائية>
DRIVER               trial.driver@masar.test        <كلمة مرور عشوائية>
EXTERNAL_REQUESTER   trial.requester@masar.test     <كلمة مرور عشوائية>
```

**انسخها إلى مدير كلمات مرور، لا إلى ملف نصي داخل المشروع.**

## الخطوة ٢: التحقق

```bash
./scripts/staging-test.sh
```

يفحص تسعة أمور ويطبع ✅ أو ❌ لكل واحد:

1. **صحة الخدمات** — الخمسة في حالة `healthy`
2. **عزل الشبكة** — قاعدة البيانات وOSRM والتطبيق **غير مكشوفة** للخارج
3. **HTTPS** — يعمل، وHTTP يحوّل إليه، والرؤوس الأمنية موجودة
4. **التشفير** — AES-256-GCM عبر مكتبة معتمدة
5. **مسارات سعودية معروفة** — المسافات والأزمنة تطابق قياسات مرجعية
6. **فحص الإقلاع** — يقبل إعداد البيئة التجريبية
7. **البيانات** — كلها موسومة، ولا صف بيانات حقيقية
8. **النسخ الاحتياطي** — أرشفة WAL تعمل
9. **الحزمة الآلية** — اختبارات الوحدة والمحرك

**لا تستخدم البيئة قبل أن تكون النتيجة `فشل 0`.**

## الخطوة ٣: الاستخدام

افتح المتصفح على:

| الرابط | لمن |
|---|---|
| `https://localhost/` | المدير · التخطيط المركزي · مشرف المركز |
| `https://localhost/driver` | السائق (مصمَّم للجوال) |
| `https://localhost/request` | الجهة الطالبة الخارجية |

> **المتصفح سيحذّرك من الشهادة.** هذا متوقَّع: الشهادة موقَّعة ذاتيًا لأنها
> بيئة تجريبية. اضغط «متقدم» ثم «متابعة». لشهادة موثوقة ضع `fullchain.pem` و
> `privkey.pem` في `deploy/staging/certs/` وأعد التشغيل.

## الأمان — ما فُعل نيابةً عنك

| | |
|---|---|
| **المنافذ المكشوفة** | ٤٤٣ (HTTPS) و ٨٠ (تحويل) **فقط** |
| **غير مكشوف** | التطبيق (8080) · قاعدة البيانات (5432) · OSRM (5000) |
| **الشبكة الداخلية** | معزولة بلا نفاذ إلى الإنترنت |
| **الأسرار** | مولَّدة عشوائيًا عند التشغيل، في ملف بصلاحية `600`، خارج المستودع |
| **كلمات مرور الحسابات** | تُعرض مرة واحدة، لا تُحفظ في أي ملف |
| **التشفير** | AES-256-GCM إلزامي — `preflight` يمنع الإقلاع بدونه |
| **HTTPS** | TLS 1.2+ · HSTS · CSP · منع التأطير |
| **حد محاولات الدخول** | عند nginx وفي التطبيق معًا |
| **المستخدم داخل الحاوية** | غير جذر (uid 10001) |
| **إصدارات الصور** | مثبَّتة بدقة — لا `latest` |

> **لماذا لا يُكشف OSRM؟** لأنه بلا مصادقة إطلاقًا. كشفه يعني خدمة حوسبة
> مجانية لأي أحد، وتسريب مواقع منشآتك عبر أنماط الاستعلام.

## أوامر تحتاجها

```bash
# حالة الخدمات
docker compose --env-file deploy/staging/.env.staging \
  -f deploy/staging/docker-compose.staging.yml ps

# سجل التطبيق مباشرةً
docker compose --env-file deploy/staging/.env.staging \
  -f deploy/staging/docker-compose.staging.yml logs -f app

# مجموعة حسابات جديدة (كلمات مرور جديدة تُطبع مرة واحدة)
docker compose --env-file deploy/staging/.env.staging \
  -f deploy/staging/docker-compose.staging.yml \
  exec app python3 scripts/make_trial_accounts.py

# إيقاف مؤقت — البيانات تبقى
./scripts/staging-up.sh --down

# إعادة تشغيل بعد تعديل الكود
./scripts/staging-up.sh --rebuild
```

**حذف كل شيء نهائيًا** (بما فيه بيانات الطرق ومفاتيح التشفير — لا رجعة):

```bash
docker compose --env-file deploy/staging/.env.staging \
  -f deploy/staging/docker-compose.staging.yml down -v
rm -f deploy/staging/.env.staging
```

## عندما يتعطل شيء

| ما تراه | السبب الغالب | الحل |
|---|---|---|
| «خدمة Docker لا تعمل» | Docker متوقف | `sudo systemctl start docker` |
| توقّف عند تجهيز الخرائط بلا رسالة | نفاد الذاكرة | أضف ذاكرة حتى ٨ ج.ب فأكثر |
| «فشل تنزيل الخريطة» | لا إنترنت أو حجب | تأكد من الاتصال، أو نزّلها يدويًا إلى `deploy/osrm/data/` |
| «الخريطة ليست خريطة السعودية» | ملف تالف أو خاطئ | احذف `deploy/osrm/data/` ثم أعد التشغيل |
| المتصفح يرفض الاتصال | لم تجهز الخدمات | `staging-test.sh` ثم اقرأ سجل الخدمة الفاشلة |
| «Port already in use» | ٤٤٣ مستخدم | غيّر `MASAR_HTTPS_PORT` في `.env.staging` |
| نسيت كلمات المرور | تُعرض مرة واحدة | ولّد مجموعة جديدة بالأمر أعلاه |
| `preflight` يمنع الإقلاع | إعداد ناقص أو تشفير غير معتمد | اقرأ قائمة الموانع — كل مانع مذكور بسببه |

## ما هذه البيئة **ليست** له

- **ليست إنتاجًا.** شهادتها موقَّعة ذاتيًا، وبياناتها وهمية، وتقبل الصفوف
  الموسومة التي يرفضها الإنتاج.
- **ليست مكانًا لبيانات حقيقية.** لا مرضى، ولا عينات فعلية، ولا منشآت
  بعناوينها الحقيقية إن كانت حساسة.
- **ليست مقياسًا لأداء الإنتاج.** خمس خدمات على خادم واحد.
- **ليست بديلًا عن اختبار اختراق مستقل.**
